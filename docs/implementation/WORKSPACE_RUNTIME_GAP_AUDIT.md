# Codex workspace runtime gap audit

## Scope and finding

This is a source-only audit of the Codex adapter, local workspace grants and patch review, provider settings, evaluator boundary, and bounded test options. Atlas reports this folder is not registered, and the pinned `project_context` call failed; no curated project notes were used. I read the local source and test files directly. I did not run project tests, inference, browser acceptance, API integration, or provider calls, and I did not edit application source.

**Implemented:** Codex can return a text answer from a bounded, ephemeral, read-only turn. The local workspace already supports separately granted text proposals and explicit human approval before applying one.

**Not implemented:** There is no flow that sends an approved local file snapshot to Codex and moves its answer into the existing proposal review. A safe text-only flow is feasible; it must preserve explicit provider sharing consent, the normal verified target-run policy, and the server-side patch lifecycle.

## Smallest secure implementation contract (proposal)

1. Add a user-initiated “Draft with Codex” action to local file review. Require a separate, clear confirmation that the selected file text will be sent to the configured Codex target and saved with the normal project prompt/run. A local read grant is not provider-sharing consent. The existing conversation consent logic permits only selected, current, share-enabled knowledge sources; it does not grant permission to send a local workspace file. (`apps/web/src/lib/workspace-conversation-consent.ts:23-61`)
2. Reuse the existing verified Codex target run path and its provider connection, model, budget, and run-purpose checks. Include only the user-selected file text and task; omit the absolute root/path and never mount the workspace into Codex. Treat file text as untrusted evidence. The adapter already accepts a text-only request and returns text under its read-only policy. (`apps/web/src/app/api/projects/[projectId]/runs/route.ts:517-564`; `apps/worker/src/main.ts:2574-2607`; `packages/providers/src/codex/app-server.ts:798-843,1011-1033`)
3. Put the answer into the existing editable text field. Do not parse it as executable instructions, invoke native file-change tools, or apply it automatically. Let the user inspect/edit the full diff, then use the existing `source: "user_editor"` proposal route and its separate `apply_exact_patch` confirmation. The browser cannot prove model provenance, so any provenance label must be assigned by a server orchestration path rather than trusted from a client field.
4. Bind a generated answer to the file version used as model input. The current read result has no content hash, and `proposePatch` captures the file only when the proposal is later created. Add a raw-byte content hash to the read snapshot and a server-checked expected-before-hash to proposal creation; reject with `PATCH_CONFLICT` if the file changed while Codex was responding. Existing apply-time compare-and-swap only protects changes made after proposal creation. (`packages/tools/src/local-workspace.ts:634-648,808-851,909-919`; `apps/web/src/lib/local-workspace-api.ts:469-507`)
5. Cap model input/output below the workspace's general 8 MiB file limit and reject oversize answers. The local file limit is a filesystem bound, not a suitable model-context bound. Do not silently truncate the source snapshot.

If retaining file text in normal project prompt versions is unacceptable, the current conversation path is unsuitable. A separate ephemeral endpoint would need to share the existing verified-target, usage-reservation, cancellation, and audit controls; calling `executeCodexTurn` directly from a new route would skip those orchestration checks. No such ephemeral target-run helper is present in the inspected flow.

## Security blockers to resolve before implementation

- **Provider data transfer:** A local read approval currently authorizes local browsing only. Require an explicit per-action decision to send the selected file text to Codex. The current knowledge-source consent rules reject sources marked local-only; do not treat the workspace grant as equivalent consent.
- **Prompt retention:** The simplest existing Codex conversation path persists prompt text as a project prompt version. State that consequence in the confirmation, or design a genuinely ephemeral path with the same target verification and budget checks.
- **No workspace capability for Codex:** Do not loosen `read-only`, mount the project root, or enable shell/file-change tools. The adapter refuses tool/approval requests and can safely produce a replacement string without direct filesystem access.
- **Backend authorization:** Preserve same-origin checks, server root allowlisting, active project-bound write grants, strict input validation, review, and apply-time hash checks. Never let a model result bypass `LocalWorkspaceGateway` or apply from the generation action.
- **Stale input:** Add the pre-proposal source-hash check described above. Current tests cover file changes after proposal creation, but not changes between model input and proposal creation.
- **Bounded text:** Add explicit model-context and answer limits. The local reader permits files up to 8 MiB; the turn adapter itself does not impose a workspace-specific text limit.

## Bounded test execution feasibility

The environment has bubblewrap 0.6.1, Node 22.23.2, and the project Vitest launcher. A minimal `bwrap --unshare-all` run with a read-only system mount, private `/tmp`, cleared environment, and `/usr/bin/true` exited successfully. The probe did not mount the project or home directory and was not a project test. The kernel reports 63,526 maximum user namespaces; the optional `unprivileged_userns_clone` sysctl path is absent, but the successful probe demonstrates that this bubblewrap profile can start here.

**Conclusion:** The bounded unit tests above can be run without an unrestricted shell by invoking the exact Vitest entry point inside bubblewrap, binding the project and the specific Node runtime read-only, clearing the environment, unsharing network/process/mount namespaces, and providing only private writable temporary/cache locations. The relevant workspace tests use temporary fixture roots and the Codex adapter tests use mocks. Keep browser acceptance, database/API integration, provider smoke, and network tests out of this bounded run. No Node/Vitest process and no project tests were run in this audit, as requested.

## Recommended bounded next change

Implement only the user-triggered, consented text-draft handoff into the existing editor and proposal review. Reuse the verified Codex target run path; keep evaluator policy and Codex sandbox unchanged; add the pre-proposal content-hash check and input/output caps. Add offline tests for consent gating, fake model output, missing/expired grants, source changes during generation, and “proposal only until explicit apply.”
