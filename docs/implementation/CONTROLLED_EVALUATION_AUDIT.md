# Controlled evaluation wiring audit

**Date:** 2026-10-16  
**Scope:** Read-only trace of controlled batch evaluation from web setup and APIs through worker execution, persisted report, history projection, and candidate decision. No tests, database operations, migrations, provider calls, or application changes were performed for this audit.

## Finding

The server and worker contain a bounded development/holdout evaluator with frozen paired evidence, but Pengujian still exposes only the older one-case development pilot. A controlled run can be submitted through the APIs, yet the page cannot create or review one. This leaves the required batch and holdout journey incomplete and makes a controlled record unsafe to open in the current result view.

## Connected backend path

1. `ControlledEvaluationRequestSchema` validates 2–20 unique cases, requires both development and holdout, and accepts one to three distinct Original/RAG/GraphRAG arms ([contracts](../../packages/contracts/src/index.ts:422)). The agent resolves each arm's evidence before target calls, strips labels and verification data from target requests, hashes the frozen manifest and paired responses, then validates and freezes the report ([agent evaluator](../../packages/agent/src/controlled-evaluation.ts:107), [manifest validation](../../packages/agent/src/controlled-evaluation.ts:307)).
2. `POST /runs` validates the saved baseline and candidate versions, prompt hashes, source versions/permissions, and active GraphRAG snapshot, then persists `controlledEvaluation` in the run snapshot ([runs route](../../apps/web/src/app/api/projects/%5BprojectId%5D/runs/route.ts:150), [prompt validation](../../apps/web/src/app/api/projects/%5BprojectId%5D/runs/route.ts:228), [source and graph validation](../../apps/web/src/app/api/projects/%5BprojectId%5D/runs/route.ts:273)). `POST /experiments` can attach matching controlled metadata to that run ([experiments route](../../apps/web/src/app/api/projects/%5BprojectId%5D/experiments/route.ts:337)).
3. The worker revalidates the stored configuration and saved prompt snapshots, then calls `executeControlledEvaluationBatch`; each pair uses the same frozen evidence context for baseline and candidate. It records request/response telemetry and persists the report on `run.completed` as `payload.controlledEvaluation` ([worker dispatch](../../apps/worker/src/main.ts:924), [saved prompt checks](../../apps/worker/src/main.ts:1217), [batch execution](../../apps/worker/src/main.ts:2249), [completion event](../../apps/worker/src/main.ts:2473)).
4. The experiment history and decision routes recognize controlled metadata and reuse `hasControlledEvaluationAcceptanceEvidence`. Acceptance requires a succeeded run, one intact completion report, matching run/config/prompt evidence, successful pairs, and passing configured candidate validators ([eligibility](../../apps/web/src/app/api/projects/%5BprojectId%5D/experiments/%5BexperimentId%5D/decision/controlled-evaluation-eligibility.ts:42), [decision route](../../apps/web/src/app/api/projects/%5BprojectId%5D/experiments/%5BexperimentId%5D/decision/route.ts:105)). No candidate is activated by the worker or this decision route.

These server checks provide useful integrity boundaries: exact saved prompt versions are checked again, source manifests must match the requested versions, paired answers bind prompt/request/context/answer hashes, and GraphRAG fallback is rejected. The manifest hash is an integrity check, not a signature against a privileged database writer.

## Gaps and risks

| Severity | Finding | Evidence and next fix |
| --- | --- | --- |
| **P1** | The page cannot start a batch/holdout evaluation. | `ExperimentsWorkspace` stores only `ExperimentPilotRecord[]` and its form calls `startPilot`; the form selects one arm and accepts one input. The imported batch parser, request/report schemas, and report download helper have no call sites ([component state](../../apps/web/src/components/experiments-workspace.tsx:355), [pilot form](../../apps/web/src/components/experiments-workspace.tsx:975), [dormant helpers](../../apps/web/src/components/experiments-workspace.tsx:275)). Add baseline/candidate version selection, a validated batch dataset flow, and a controlled-evaluation run request. Keep the existing pilot explicitly labeled exploratory. |
| **P1** | Controlled reports cannot be read by the page; selecting a controlled history record can dereference pilot-only metadata. | The worker emits `payload.controlledEvaluation`, while the page listens for `run.completed` and parses only `payload.result` as an optimization report ([worker event](../../apps/worker/src/main.ts:2477), [page event handler](../../apps/web/src/components/experiments-workspace.tsx:725)). The page state is pilot-only, and its details assume fields such as `metadata.arm` and `metadata.sources` that controlled metadata does not have ([record state](../../apps/web/src/components/experiments-workspace.tsx:366), [pilot-only detail fields](../../apps/web/src/components/experiments-workspace.tsx:1352)). Implement a discriminated union renderer, parse and validate `controlledEvaluation`, and show per-case baseline/candidate evidence, split, validators, usage, latency, and JSON export. |
| **P2** | The controlled contract permits partial A/R/G comparisons. | The schema permits one to three arms, and configuration validation only checks each supplied arm ([contracts](../../packages/contracts/src/index.ts:433), [agent configuration check](../../packages/agent/src/controlled-evaluation.ts:271)). If the formal v1.4 Original/RAG/GraphRAG comparison is mandatory for this experiment type, require all three arms server-side; otherwise label subset comparisons exploratory and provide a full-comparison setup. |
| **P2** | Subjective quality is not captured per case, and optimizer overhead is absent from this report. | Cases without deterministic verification receive `judgment: "subjective"`; the UI/API has only an overall accept/reject/inconclusive decision. The report also hard-codes `optimizerLineage: not_used` with no link to the candidate's optimization run ([judgment derivation](../../packages/agent/src/controlled-evaluation.ts:680), [report construction](../../packages/agent/src/controlled-evaluation.ts:237)). Add structured human case ratings/comments and link the candidate's optimizer run or explicitly report optimization cost as unavailable/separate. |
| **P2** | The controlled acceptance predicate lacks direct focused tests. | Worker tests cover holdout-label isolation, same-context pairing, GraphRAG fallback, partial failure, cancellation uncertainty, and no auto-activation ([worker tests](../../apps/worker/src/controlled-evaluation.test.ts:208)). The checked tree has no test file for `controlled-evaluation-eligibility.ts`; existing experiment browser coverage exercises only the one-case pilot ([pilot E2E](../../apps/web/e2e/experiments.spec.ts:28)). Add positive and mutation-negative eligibility tests plus a controlled batch E2E for report display, rejection, inconclusive decision, and evidence-gated acceptance. No tests were run during this audit.
